# Security Policy

## Scope

This repository is a curated documentation project. It does not distribute a production service or execute security tools on behalf of users. Security reports are nevertheless welcome when they concern repository configuration, malicious or unsafe links, compromised dependencies or actions, exposed secrets, harmful content, misleading security guidance, or an entry that creates unacceptable risk.

## Reporting a Security or Safety Concern

Please **do not publish sensitive details in a public issue** when a report could create risk for users or third parties. Submit a confidential report through the repository’s [private security-advisory form](https://github.com/frangelbarrera/Awesome-Hacking-with-AI/security/advisories/new) when that GitHub feature is available. If the form is unavailable, open a [security or content-safety issue](https://github.com/frangelbarrera/Awesome-Hacking-with-AI/issues/new?template=security-content-review.md) containing only non-sensitive pointers and request a private follow-up channel.

A helpful report includes the affected file or link, a concise description, why it matters, safe reproduction or verification steps when appropriate, and any recommended correction. Do not include credentials, personal data, unpublished vulnerabilities, exploit payloads, or instructions for unauthorized access.

## What to Expect

Reports will be assessed for reproducibility, severity, accuracy, scope, and responsible disclosure needs. The maintainer may remove or label a resource, update a link, correct a claim, restrict content, or coordinate with an upstream owner. The repository aims to acknowledge good-faith reports within seven calendar days when contact details are available, but remediation time depends on the issue, evidence, and third-party coordination needs.

## Content Safety Concerns

If an entry appears to provide unsafe operational enablement, lacks an authorized-use boundary, misrepresents a benchmark or project status, or is materially stale, report it as a security or content-safety concern. Include the canonical source and the specific factual or safety issue when possible.

## Supported Content

The maintained content is the default branch and the documentation it links to. Historical revisions, forks, and third-party projects are outside this repository’s direct control. Their upstream maintainers remain responsible for their own code, services, models, datasets, and releases.

## Coordinated Disclosure

Where a report relates to a third-party vulnerability or unpublished issue, follow the affected vendor’s disclosure policy or use coordinated disclosure guidance from [CERT/CC](https://certcc.github.io/CERT-Guide-to-CVD/) and [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Vulnerability_Disclosure_Cheat_Sheet.html). This repository should not be used to publish sensitive details before responsible disclosure is complete.
